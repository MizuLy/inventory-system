# AGENTS.md

This file provides guidance to AI coding agents (including Claude Code) when working with code in this repository.

## Stack

Spring Boot 4.1.1 / Java 21 / Maven (wrapper included). Spring Data JPA + MySQL, Spring Security, Bean Validation, Lombok, springdoc-openapi (Swagger UI). Base package: `com.mizu.inventory`.

## Commands

Use the Maven wrapper (on Windows PowerShell: `.\mvnw.cmd`; in Git Bash: `./mvnw`).

- Run the app: `./mvnw spring-boot:run`
- Build: `./mvnw clean package`
- All tests: `./mvnw test`
- Single test class / method: `./mvnw test -Dtest=InventoryApplicationTests` / `./mvnw test -Dtest=ClassName#methodName`

No linter is configured. Lombok is wired via `annotationProcessorPaths` in the compiler plugin in `pom.xml`; keep it there when editing the build.

## Configuration state

- A git-ignored `.env` holds `DB_HOST`, `DB_USER`, `DB_PASS`. `application.properties` loads it with `spring.config.import=optional:file:.env[.properties]` (so run from the project root) and builds the MySQL URL as `jdbc:mysql://${DB_HOST}:3306/inventory`. The `inventory` database must already exist.
- Schema is generated by Hibernate (`spring.jpa.hibernate.ddl-auto=update`); there is no Flyway/Liquibase. `update` can't add NOT NULL columns to tables that already have rows.
- Spring Security is on the classpath with no `SecurityFilterChain` defined, so default security (all endpoints authenticated, generated password) applies, including Swagger UI.

## Architecture

Feature-packaged layout: each domain gets its own package (`category/`, `product/`) containing entity, repository, service interface + `*Impl`, controller, and a `dto/` subpackage (`*Request`, `*Response`). `category` is the reference implementation of this pattern; `product` currently has only the `Product` entity (`@ManyToOne` to `Category`, `sku` unique, `name` not unique); it has no repository, service, DTOs or controller yet.

Conventions seen in `category`:
- Entities use Lombok `@Getter/@Setter/@Builder/@NoArgsConstructor/@AllArgsConstructor`, `GenerationType.UUID` ids, and `@CreationTimestamp`/`@UpdateTimestamp` audit columns.
- Controllers return DTOs / `Page<DTO>` directly (no `ResponseEntity`); list endpoints use `@PageableDefault`.
- Services are `@Transactional` (`readOnly = true` for reads), map entity→DTO with a private `res(...)` helper, and constructor-inject via `@RequiredArgsConstructor`.
- Services throw `ResponseStatusException` (404 not found, 409 duplicate name); `common/exception/GlobalExceptionHandler` returns the reason as a plain string. Its `RuntimeException` catch-all returns 400 for any other runtime error.
